# gt4setup

One command-line tool for the "make the game code from your own disc" steps of the GT4
recomp (GT4 USA, SCUS-97328). It replaces the Python scripts those steps used, so players
need no Python. Standard C++17 and the standard library only; it builds with MSVC and with
clang / llvm-mingw.

## Build (standalone)

```powershell
& 'C:\Program Files\Microsoft Visual Studio\18\Community\Common7\Tools\Launch-VsDevShell.ps1' -Arch amd64 -HostArch amd64 -SkipAutomaticLocation
cmake -S recomp\gt4setup -B recomp\out\gt4setup -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build recomp\out\gt4setup
```

It is not part of `recomp\CMakeLists.txt` yet.

## Commands

| Command | Replaces |
|---|---|
| `gt4setup extract-boot <iso> <outdir>` | `tools\extract_boot_files.py` |
| `gt4setup core-to-elf <CORE.GT4> <CORE.elf>` | `tools\core_to_elf_gt4.py` |
| `gt4setup vu-images <CORE.elf> <outdir>` | the VU part (step 6) of `tools\gt4_embedded_regions.py` |
| `gt4setup vu-translate [--vu0] [--no-sticky] [--entries pc,...] <code.bin \| kicks.bin> <out_dir>` | `recomp\gt3-tools\vu1_translate.py` |
| `gt4setup vu-disasm <code.bin \| kicks.bin> [start_hex end_hex]` | `recomp\gt3-tools\vu1_decode.py` (as a script) |
| `gt4setup late-functions <old core-generated> <new ps2_recomp output> <out .cpp>` | `analysis\design\multi-monitor\scripts\make_late_functions.py` |

- **extract-boot** copies every file outside `GT4.VOL` and the `EPSON` folder from the ISO
  and writes `boot-files-manifest.json` (SHA-256 of each file; JSON indent 1, CRLF line ends,
  as the Python script wrote it on Windows). The ISO is only read.
- **core-to-elf** inflates `CORE.GT4`, checks its SHA-256 (`85d26aa8...`) and startup code,
  and writes `CORE.elf` (sha256 `80708a3e...`) plus `CORE.json`. No instruction is patched.
- **vu-images** writes `gt4_vu0_0x6d3280_raw.bin`, `gt4_vu0_code_image.bin` (4 KiB),
  `gt4_vu0_listing.txt`, `gt4_vu1_0x624dd0_decoded.bin`, `gt4_vu1_code_image.bin` (16 KiB)
  and `gt4_vu1_listing.txt`, the files in `analysis\recomp-prep\vu\`. The Python script found
  the two MPG uploads by analysing the whole CORE; here they are pinned to GT4 USA: every
  instruction the constants come from (upload calls at 0x4a0584 / 0x4a05a4, the decoder call
  at 0x4a0500, the LCG at 0x4aa308) is checked word for word, the LCG seed is read from
  0x62a03c, and both images must decode with no reserved pairs to their known SHA-256.
- **vu-translate** reads the same generation options as the Python script from the
  environment (`GT3_VU1T_SIMD`, `_ZERO_FAST`, `_STICKY`, `_SIMD_MINMAX`, `_NORM_SKIP`,
  `_VEC_STORE`, `_LOCALS`, `_WHOLE_READY`); `--no-sticky` = `GT3_VU1T_STICKY=0`. Output
  comments still say "Generated by gt3-tools/vu1_translate.py" so the files stay identical.
- **late-functions** output still names `make_late_functions.py` in its header, for the same reason.

## The shipped files, from a disc

```powershell
gt4setup extract-boot "<GT4 USA iso>" game
gt4setup core-to-elf game\CORE.GT4 game\CORE.elf
gt4setup vu-images game\CORE.elf analysis\recomp-prep\vu
gt4setup vu-translate --no-sticky --entries 1b08,1b10,1b30,1b38,1b58,1b60,1b80,1b88,1ba8,1bb0,1bd0,1bd8,1bf8,1c00,1c20,1c28,1c48,1c50,1c70,1c78,1c98,1ca0,1cc0,1cc8,1ce8,1cf0,1d10,1d18,1d38,1d40,1d60,1d68,1d88,1d90,1db0,1db8,1dd8,1de0,1e00,1e08,1e28,1e30,1e50,1e58,1e78,1e80,1ea0,1ea8,1ec8,1ed0,3d50,3ea0 analysis\recomp-prep\vu\gt4_vu1_code_image.bin recomp\ps2xRuntime\src\lib\vu\generated_gt4
gt4setup vu-translate --vu0 --entries 58,78,b8,f8,2e8,308,460,478,548,678,700,858,900,930 analysis\recomp-prep\vu\gt4_vu0_code_image.bin recomp\ps2xRuntime\src\lib\vu\generated_gt4
gt4setup late-functions analysis\core-generated <ps2_recomp output with the gap entry points> recomp\ps2xRuntime\src\gt4_late\gt4_late_functions.cpp
```

The VU1 image ships generated with sticky flags off (commit 6cb09c2) and the VU0 image with
the 14 VCALLMS entries (`analysis\phase5\specs\critique.md`), not the 10 in `vu1-translator.md`.

Not ported: `tools\gt4_data_entry_points.py` (the function list ships as config), and the
rest of `gt4_embedded_regions.py` (evidence CSVs for the analysis, not build inputs).

## Verification

`analysis\design\release-pipeline\gt4setup-check\check.ps1` runs every command and compares
the outputs with the reference files and with the Python scripts (results in `results-*.txt`
there). All outputs are byte-identical.
